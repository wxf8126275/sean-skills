# `sean run <name> [start_n] [--dry-run] [--no-fix] [--lite]`

按 plan 逐 task 执行 TDD 循环，完成后做回归与交接。

`sean task <name> <n>` 与 `sean run` 流程相同，但只执行指定 task，且**不检查依赖**（用户责任）。

---

## 参数

| 参数 | 含义 |
|---|---|
| `start_n` | 从第 N 个 task 开始（默认 1） |
| `--dry-run` | 只解析计划、校验依赖、输出表格，不执行 |
| `--no-fix` | 测试失败不自动修复，标记 failed 后停止 |
| `--lite` | 轻量模式：跳过 artifacts catalog / review findings / 五维评估 / 完整 handoff（详见文末） |

---

## Pre-flight

1. **取状态**（不要导出全量）：
   ```bash
   python3 <sean-root>/scripts/sean_state.py get <name> --full
   ```
   输出任务级明细；如需字段定义再读 `state-schema.md`。
2. 读 plan：`docs/plans/<date>-<name>.md`。缺失则报错并提示 `sean plan <name>`。
3. 确定起始 task 序号。
4. **并行检测**：扫描 `start_n`..end，若 ≥2 个 task 同时满足 `parallel_safe: true` 且其 `depends_on` 全部 `done`，询问用户：
   ```
   ⚡ 检测到 N 个可并行任务: Task 2, 3, 5
   是否启用子智能体并行执行？（并行缩短墙钟时间，但 token 成本更高）
     是 — 并行分发
     否 — 串行执行（默认，更省 token）
   ```
   只有 1 个 parallel_safe → 不询问，直接串行。
5. `conventions.md`：本会话首次执行时读一次，后续复用，不重复读。

---

## `--dry-run`

不执行任何代码。只输出：

1. 表格：`# | Task | Complexity | Depends On | Parallel Safe`
2. 依赖校验（无环）
3. 测试数与耗时估算
4. 下一步提示：`sean run <name>`

---

## 执行循环（每个 task）

### 1. 依赖检查

所有 `depends_on` 必须为 `done`。否则提示用户：先跑依赖 / 跳过。

**多端 feature**（state 有 `targets` 键时）额外两条：

- 只执行 `target` 匹配当前端的 task；跨端 task 留给对应端工程师（用 `sean task <name> N`）。
- 每个 task 的测试必须从 `docs/contracts/<date>-<name>/cases/` 加载**共享用例**，不要自造等价断言——这是消除跨端逻辑漂移的唯一手段。
- 全部端完成后仍需跑 `sean_parity.py`，PASS 才能置 `DONE`。详见 `references/multi-target.md`。

### 2. 上下文加载（**严格遵守 Token 纪律**）

- **禁止**"读所有 files_modify"。
- 只读本 task 要改的**函数/类所在区域**：先 `grep -n "<symbol>\|<class>\|<import>"`，再 `offset+limit` 定向读。
- 需要匹配代码风格时，读 `files_create` 的父目录中**一个**同级文件的前 50 行即可，不整目录扫描。
- 测试文件：若已存在则只读其 `import` 段与最相近的 1-2 个用例；不存在则读同目录 1 个样板测试。
- `conventions.md` 已在 Pre-flight 读过 → 直接复用。

### 3. 写失败测试

- 位置：plan 中 `test_file`（不存在则创建）。
- **质量门**：至少一条断言验证 task 描述的**行为**。以下判为无效测试，必须重写：
  `assert True` / `assert 1 == 1` / 空测试体 / 无断言 / 断言实现细节而非行为。
- 测试必须足够具体，使 RED 的含义是"功能未实现"而非"测试写错"。

### 4. 跑测试，确认 RED

```bash
<test command> -q --tb=short     # 或项目等价的静默输出
```

- PASS → 测试写错了（测的是已有行为），改测试。
- ERROR（非 fail）→ 修测试 setup。
- **RED 确认**：记录**首个失败断言**及其原因（1-3 行），证明测试确实覆盖了新行为。
- **输出预算**：只读首个 failure 的尾部 ≤30 行。**不要**回显整个测试会话。

### 5. 写最小实现

只写让测试通过的最小代码。不过度设计。

### 6. 创建声明的产物（若 task 有 `artifacts`）

- 按 plan 声明的路径写文件（`migrations/`、`scripts/`、`config/`）。
- 每个产物文件头部带反向引用注释：
  ```
  -- Requirement: <feature> (docs/requirements/<date>-<name>.md)
  -- Task: <id> (<task-name>)
  -- Generated by: sean run
  -- Catalog: docs/artifacts/<date>-<name>.md
  ```
  （shell 用 `#`，SQL 用 `--`）
- 更新状态：`declared` → `created`（`sean_state.py` 的 `set` 或 `add-task` 时写入）。
- **不要自动执行产物**。执行是独立动作（见 `cmd-artifact.md`）。

### 7. 再跑测试，确认 GREEN

同一命令再跑一次即可。**不要求"重新从零启动进程再跑一遍"**——这与 Post-execution 的整体回归重复。

### 8. 轻量自审

逐条对照（基于你刚写的代码，不要重新读整个文件）：

- 函数 ≤ 40 行？文件 ≤ 400 行（不含测试）？
- 无 `any` / `object` 类型？
- 错误处理显式（无裸露 `except:` / 空 catch）？
- 无 `TODO` / `FIXME` / `HACK`？

任一项不满足 → 就地修正后再继续。

### 9. 落状态 + 写报告

```bash
python3 <sean-root>/scripts/sean_state.py task-status <name> <n> done \
  --tests-total <N> --tests-passed <N> --fixes <N> \
  --report docs/test-reports/<date>-<name>/task-<n>-<name>.md
```

报告用 `templates/test-report.md`，**≤15 行**，只保留：结果计数、RED 观察（1 行）、GREEN 观察（1 行）、结论。

## Fix Loop（测试未通过时）

`--no-fix`：标记 `failed` 并 STOP，输出失败详情。

默认（自动修复）：

```
for attempt in 1..3:
  a. 读取首个 failure 的尾部 ≤30 行（不是整个输出）
  b. 分析根因：import? 逻辑? 缺依赖? 类型不匹配? API 误用?
  c. 定向读相关源码（grep 定位后读片段）
  d. 改实现（**绝不改测试**）
  e. 重跑测试
  f. GREEN → break
  g. 仍 RED 且根因未变 → 早停（不浪费尝试）
```

3 次后仍 RED → 标记 `failed`，STOP。
**修复质量门**：确认修复针对根因，而不是把错误吞掉。

**连续 2 个 task 失败 → 中止整个 run**，输出 blocker 报告。

## Post-execution（全部 task 完成后）

1. **端到端回归**（整个 run 只做**一次**）：
   ```bash
   <test command> <feature test dir> -q --tb=short
   ```
   失败则整体 `INTEGRATION_FAIL`，列出冲突点。
2. **写 handoff**：按 `references/cmd-handoff.md` 的**精简模式**生成（不重扫源码）。
3. **建议 commit message**：
   ```
   feat(<scope>): implement <feature-name>

   - <task 1 summary>
   - <task 2 summary>

   Tests: N passed
   Regression: passed
   Artifacts: N database, N batch, N config
   ```
4. **落状态**（一次 snapshot 覆盖整个 run）：
   ```bash
   python3 <sean-root>/scripts/sean_state.py feature-status <name> DONE
   python3 <sean-root>/scripts/sean_state.py snapshot run <name> \
     --files-created a.py,b.py --files-modified c.py
   ```
   只有单个 task 与回归全绿才置 `DONE`；否则 `BLOCKED` 或 `INTEGRATION_FAIL`。
5. **汇报 3 行**：任务结果 / 回归结果 / 下一步。

## `--lite`（轻量模式）

跳过以下全部内容，只保留核心 TDD 闭环：

| 跳过项 | 省下的成本 |
|---|---|
| `docs/artifacts/<date>-<feature>.md` catalog | 一次完整表格生成 |
| review 五维评估 + findings 生成 | 一次全 feature 扫描 |
| 完整 handoff.md（改为 5 行摘要追加到 task 报告） | 一次全量文件清单整理 |
| 逐 task 的详细报告（改为每个 task 3 行） | N 份模板渲染 |

保留：TDD 循环、单次回归、state 落盘、一行 handoff。

适用：内部工具、脚手架、试验性 feature；不适用于需要跨 Agent 接力交付的功能。
